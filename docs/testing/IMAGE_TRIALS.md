# Испытания локальных изображений на Windows 11 / RTX 5070

Реальный движок и веса устанавливаются отдельно владельцем. Кандидат: современный ComfyUI с `/api/jobs/{id}/cancel` и стандартными узлами CheckpointLoaderSimple / CLIPTextEncode / EmptyLatentImage / KSampler / VAEDecode / SaveImage. Это адаптер обычного checkpoint workflow, не универсальный импорт произвольного Comfy workflow. Старый глобальный `/interrupt` не используется. Окончательная конфигурация D-06 не выбрана до аппаратных испытаний.

1. Распакуйте внутренний portable ZIP в доступную для записи папку. Запустите основной EXE, настройте LM Studio на числовой loopback endpoint. Вручную загрузите LLM и проверьте обычный ответ в чате.
2. Вручную запустите ComfyUI на loopback. В галерее раскройте генератор, задайте endpoint, сохраните настройки и проверьте возможности. Проверка возможностей отправляет адресную отмену нового случайного UUID, которого движок не знает; workflow при этом не создаётся.
3. Выберите уже установленный checkpoint. Не запускайте параллельно другие задачи. Запишите версии Windows, драйвера, LM Studio, ComfyUI и hash/название LLM и checkpoint. Скрипт собирает часть этих сведений, но не проверяет фактические флаги запуска low-VRAM; их указывает оператор.
4. Запустите PowerShell 5.1 или новее из папки программы:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\docs\testing\Run-ImageTrial.ps1 -PortableRoot $PWD -LoadedModelId "ID загруженного экземпляра LM Studio" -Checkpoint "имя.safetensors" -EngineModeLabel lowvram -CheckpointFile "C:\Models\имя.safetensors" -Execute
```

Скрипт делает одну реальную генерацию, сохраняет JSON и PNG в `diagnostics/image-trials`, проверяет checksum результата, неизменность списка загруженных экземпляров и возможность получить короткий ответ той же LLM после изображения. `-Execute` разрешает эти два вычисления; без него результат BLOCKED и генерация не запускается. Скрипт не меняет настройки, не запускает движки, не скачивает/загружает/выгружает модели и не снимает блокировку неопределённой задачи автоматически. Ключ запуска/сеанс не записываются в отчёт. Отчёт содержит prompt и ответы: проверяйте его перед публикацией.

Повторите с `-Case cancel` и достаточно длинной задачей. Отмена считается подтверждённой только после наблюдения внешнего `in_progress`, адресной отмены собственного UUID и подтверждения `cancelled`. Слишком быстрая задача даёт BLOCKED, а не ложный PASS. Скрипт не использует глобальные interrupt/free/unload endpoints.

Сравните вручную режимы CUDA/low-VRAM/CPU, каждый раз самостоятельно перезапуская движок с нужными флагами. Отдельно проверьте offline, нехватку памяти, недостаточный порог VRAM, таймаут, обрыв связи после отправки, перезапуск Таверны, проверку/восстановление известного результата, CPU/экономный профиль и продолжение чата. Не создавайте OOM увеличением нагрузки без контроля системы. Измерьте VRAM до/во время/после и оцените качество PNG визуально. Snapshot free VRAM не гарантирует успех, кеш движка может остаться после окончания задачи; контрольная генерация LLM выявляет практическую возможность продолжить диалог.

PASS скрипта относится только к описанным API/resource/co-existence подпроверкам. Оценка качества, сравнение конфигураций, акустика/анимация, перенос portable, официальный AT-09 и подписанная приёмка остаются отдельными критериями. GitHub Windows runner не заменяет Windows 11 / RTX 5070 / настоящий LM Studio. Результаты doubles в unit/browser тестах не являются аппаратными испытаниями.
