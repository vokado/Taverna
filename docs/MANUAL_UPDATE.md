# «Таверна»: ручное обновление портативной версии

Обновления не загружаются, не проверяются и не устанавливаются автоматически.
Новая версия устанавливается **только в отдельный новый каталог**, а
работающая программа и прежние файлы не заменяются. Это позволяет вернуться
к прошлой версии без вмешательства в её данные.

## Обновление через окна программы

1. Закройте «Таверну» кнопкой **«Завершить приложение»**. Убедитесь, что не
   осталось работающего процесса Taverna.exe.
2. Получите ZIP нового выпуска из доверенного источника. По возможности
   сверьте его SHA256 с опубликованной контрольной суммой.
3. Распакуйте новый ZIP во **временную папку**. Запустите
   **Taverna-Updater.exe** из этой папки.
4. Выберите каталог прежней установленной «Таверны», исходный ZIP нового
   выпуска, затем родительскую папку для новой установки.
5. Введите **новое имя папки** и, если оно опубликовано, ожидаемую SHA256.
6. Мастер проверит ZIP, создаст полную резервную копию старых данных и
   подготовит новую установку в временной папке рядом с назначением.
   При любой ошибке временная папка удаляется, а старая не заменяется.
7. После сообщения об успехе откройте **Taverna.exe** из новой папки.
   Убедитесь, что персонажи, истории и материалы читаются, проверьте
   целостность JSON в интерфейсе.

**Важно:** операция требует места для новой программы, копии пользовательских
данных и резервной копии. Не выбирайте назначение внутри прежней установки
или наоборот. Старую установку и резервную копию не удаляйте, пока новая
не пройдёт проверку.

## Безопасность и откат

- Если старая программа ещё работает, обновление не выполняется.
- ZIP не должен содержать пользовательские данные, подозрительные пути,
  ссылки или обязательные файлы с неверным именем.
- Новая установка получает отдельную копию данных; исходная остаётся
  неизменённой, за исключением сохранённого перед обновлением архива.
- Созданная перед обновлением резервная копия находится в каталоге
  `backups` старой установки. Ручные архивы не удаляются политикой
  автоматического резервирования.
- Для отката **закройте новую «Таверну» и запускайте старую папку**.
  Данные, накопленные уже в новой версии, автоматически не переносятся
  назад: используйте отдельный проверенный экспорт и сверку.
- Файлы из внешних сетевых путей/UNC и неподтверждённые ZIP не рекомендуются.
  Проверка SHA256 обнаруживает изменение архива относительно указанного
  значения, но не устанавливает подлинность издателя сама по себе.
- Перед передачей архива диагностики третьим лицам просмотрите содержимое.

## Автоматизированная проверка для администраторов

Мастер также поддерживает явный запуск с параметрами
`--source`, `--archive`, `--destination` и необязательным
`--sha256`. Это используется в Windows CI, но не требуется обычному
пользователю. Ни сетевые запросы, ни автоматическая установка не
выполняются.

## Что этот механизм не делает

Он не меняет работающую установку на месте, не удаляет старые версии и не
утверждает, что аппаратные тесты LM Studio/RTX5070 выполнены. После
обновления необходимо испытать конкретную сборку на целевой Windows.
