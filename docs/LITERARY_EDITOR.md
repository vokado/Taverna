# Контракт этапа13 — редактор, материалы и инструменты

Перед реализацией: EDIT-001–004, MED-008, TOOLS-001–003; D-02/09/10, общий допуск01–16. Этап12 имеет доступную регрессию190/12; аппаратные image/LMStudio критерии не подменяются работой редактора. Статус13 IN_PROGRESS, контракт не является PASS.

Рукопись — отдельный JSON-документ: название/автор/язык, упорядоченные главы с UUID, текстом и явными ссылками/медиа. Изменения CAS; каждое опубликованное состояние сохраняется в отдельной immutable версии. Восстановление старой версии создаёт новую, исходные версии остаются. Поиск не исполняет regex/HTML. Черновики сохраняют raw независимо от публикации.

ИИ использует ту же очередь и роль editor; преобразование выбранного диапазона чата создаёт предложение отдельного документа. Источник читается согласованным snapshot с branch revision, источник не редактируется. Переработка/стиль/сокращение/расширение/связность создают сохранённое предложение и diff; принятие требует исходных ревизий, отказ не изменяет рукопись. Coherence выдаёт заметки, не перезаписывает прозу. Модель не получает произвольные файловые пути или инструменты.

TXT: UTF-8, главы и печатные URL/подписи. Markdown: ZIP с .md и относительными media-файлами, чтобы ссылки переносились вместе с текстом. HTML: самостоятельный UTF-8 файл, escaped text/links и data-URI собственных проверенных media, без скриптов. EPUB3: mimetype первым без сжатия, container/package/nav/XHTML/идентификаторы/ссылки/manifest/spine; изображения совместимого типа, WebP преобразуется в PNG; поддерживаемое встроенное аудио MP3, неподдерживаемый EPUB-аудиоформат вызывает ошибку до выдачи неполного файла. Чтение EPUB реальным reader/EPUBCheck — отдельные проверки, не заменяемые XML parse.

Материалы: существующие изображения плюс документы UTF-8 TXT/MD/JSON, PDF и DOCX как вложения с проверкой контейнера/размера/типов, без исполнения макросов/HTML. Исходный файл неизменяемый с hash, JSON metadata/теги/поиск/ссылки на мир/сцену, downloads attachment; preview только безопасный извлечённый текст. Офисные контейнеры требуют ограниченной распаковки и отклонения external relationships/макросов/активных частей. Документные извлекатели выбираются по доступным проверкам; неподдержанный файл отклоняется явно.

Заметки/закладки/словарь/шаблоны/генераторы имён — собственные versioned JSON записи и визуальные формы. Привязки истории/ветви/сцены/события проверяются. Редактор событий работает через уже реализованный world reducer с preview и CAS, не прямой записью в branch-state. Пользовательский шаблон — ограниченная подстановка именованных строк, не eval/OS-команды; preview и явные права перед созданием заметки/главы. Полный менеджер прав/плагины/планировщик —14, не объявляется завершённым раньше.

Проверки: CAS/история/restore/невалидный ввод/опасные URL и файлы, все четыре экспорта с кириллицей/главами/внутренними ссылками/media/целостностью EPUB, отмена/ошибка/устаревший AI результат и reject без изменения оригинала, исходный чат byte-equal, несколько UI редакторов/черновики/reload, каждый TOOLS подпункт. Реальные LMStudio и внешние reader fixtures отмечаются отдельно при отсутствии.

## Реализованное использование

В разделе «Литературный редактор» создайте рукопись и главы, задайте название/автора/язык, отредактируйте текст. Структура меняется кнопками добавления, перемещения и удаления главы в новой редакции. «Опубликовать рукопись» проверяет текст, главы, UUID, ссылки и исходную ревизию. Удалённые главы сохраняются в прежних версиях; восстановление создаёт новую версию. Список рукописей выдаётся порциями50, полный текст открывается отдельно; чтение списка не загружает историю всех редакций. Поиск сопоставляет буквальный текст без regex. Начальные пределы:500глав,1МиБ текста главы,2МиБ UTF-8 текста рукописи; эти ресурсные ограничения не являются SLA целевого ПК.

Raw JSON хранится отдельно от последнего состояния форм. При публикации используется JSON из редактора; невалидный raw сохраняется в черновике и не заменяет опубликованную рукопись. Незавершённые ID допускаются в draft shape, при публикации проверяются настоящие UUID/ссылки. Несколько черновиков имеют собственные ID/revision, исходная ревизия рукописи не повышается при восстановлении черновика.

ИИ: сначала опубликуйте исходник, выберите главу и при необходимости выделите фрагмент. Выберите уже загруженный экземпляр или профиль editor. Режимы: переработка, стиль, сокращение, расширение, связность. Замечания о связности читаются отдельно и не записываются вместо прозы. Остальные результаты показывают original/after/unified diff; подтвердите или отклоните. При конкурентном изменении принятие старого предложения запрещено, предложение можно прочитать/отклонить. Отмена/сбой не меняют оригинал. Преобразование выбранных сообщений чата использует согласованный snapshot и имена авторов из снимков карточек, создаёт отдельную рукопись; ветвь, сообщения, память и RPG не изменяются. Запрос до200выбранных сообщений/256КиБ исходника — проверяемая граница одного AI-вызова; большой исходник обрабатывается выбранными фрагментами, модельное окно проверяется GenerationService. Значение связности/художественного качества оценивает пользователь, тестовый ответ не доказывает качество реальной LLM.

Экспорт доступен для опубликованной редакции. TXT/HTML — самостоятельные UTF-8 файлы, Markdown ZIP содержит текст и относительные ресурсы, EPUB3 содержит manifest/spine/nav/XHTML и медиа. Пустой автор не создаёт недопустимый dc:creator; пустое название отклоняется. EPUBCheck5.4.0 нашёл этот дефект до контрольной точки, исправление включено. WebP → статический PNG для EPUB, MP3 встраивается как audio с controls; неподдержанное EPUB-аудио вызывает явную ошибку вместо неполного экспорта. TXT содержит подписи медиа/адреса, бинарные вложения в TXT не поддерживаются форматом. Лимит пакета64МиБ, пути генерируются из UUID, HTML/Markdown пользовательского текста не исполняются.

## Материалы и инструменты

Документы находятся в `library/documents/{sha256}.{ext}`, структурные метаданные — versioned JSON в `data/media/materials` через общий storage. Импортирует12МиБ максимум; UTF-8 TXT/MD/JSON проверяются и имеют текстовый preview, JSON отвергает NaN/Infinity. DOCX ZIP ограничен200частями/16МиБ суммарно/4МиБ на часть/ratio200; пути, DTD/entities, external relationships, VBA/ActiveX/embeddings отклоняются. Сохраняется извлечённый текст, не офисная разметка. PDF проверяется pypdf7.1.0 BSD-3-Clause в strict mode, с ограничениями декомпрессии/деревьев/объектов; шифрование и известные активные действия/вложения отклоняются. PDF не рендерится внутри приложения и не имеет полнотекстового извлечения: доступны описание/теги/структурная проверка и скачивание исходника. Это не антивирусная гарантия для стороннего reader. Документы скачиваются attachment, исходный hash проверяется повторно. Изображения/аудио остаются в общей медиабиблиотеке, сцены/миры связываются ID.

Заметка, закладка и словарная запись создаются соответствующими кнопками. Добавляйте URL и явные привязки к миру/истории/ветви/сцене/событию/сообщению; ссылки проверяются, данные не передаются NPC автоматически. Генератор имён настраивается списками частей, seed/count; sha256-counter-v1 делает результат воспроизводимым, seed/draws/names сохраняются в JSON журнале. Архивирование не удаляет запись.

Пользовательский шаблон подставляет только объявленные `{{переменные}}` один раз, без eval/OS-команд. Настройте действие «создать заметку» или «добавить главу» и отдельно выдайте соответствующее право. Заполните переменные, выберите рукопись при необходимости, создайте предпросмотр. Предпросмотр показывает полный текст/действие/право и ничего не применяет. Подтверждение проверяет актуальную ревизию шаблона, наличие права и ревизию рукописи. Отзыв/изменение блокирует старое действие; повторное выполнение не создаёт дубликат. Preview/status/receipt и результат публикуются атомарно. Полный plugin/automation broker относится к этапу14; этот безопасный ограниченный инструмент не заменяет executable plugins.

Редактор событий доступен здесь после выбора истории и использует существующий StoryWorld/world reducer: предпросмотр, явное подтверждение, branch CAS и журнал последствий. Он не получает прямого доступа к JSON-файлам. Все перечисленные операции выполняются кнопками/формами; raw JSON необязателен.

## Повторение проверок

```text
.venv/bin/python scripts/prepare_epub_tools.py
.venv/bin/pytest -q
.venv/bin/python scripts/export_contracts.py
# app/web:
npm run types
npm run build
npm run test:e2e
```

Подготовка загружает только development tools по закреплённым SHA256 в игнорируемый `.test-tools`: EPUBCheck5.4.0, epub.js0.3.93 BSD-2-Clause и JSZip3.10.1 MIT/GPL dual (использование по MIT). Нужен Java21 в среде проверки; portable-программа, пользовательские экспортные файлы и runtime этого не требуют и не включают эти инструменты. CI готовит их перед browser tests. Реальная epub.js в Chromium читает произведённый ZIP, отображает кириллицу/изображение и переключает главы; fixture не подменяет reader. EPUBCheck отдельно проверяет результат UI-экспорта и пример с WebP→PNG/MP3, XML parse используется только для низкоуровневых assertions. Реальный LMStudio и аппаратные проверки продолжаются отдельно; HTTP doubles не называются настоящей LLM.
