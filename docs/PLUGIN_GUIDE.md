# Расширения: руководство текущей внутренней сборки

Этап 14 ещё не завершён. Работают установка и отдельные права, явный запуск, просмотр и подтверждение внутренних изменений, передача выбранных внешних файлов, одно явно подтверждаемое внешнее исполнение команды, ручные макросы и интервальные правила с просмотром результатов. **Внешняя запись файлов и сетевые операции, а также смешанные планы** остаются неподтверждёнными. Это не официальный релиз 1.0.

## Установка и разрешения

1. Откройте «Расширения», выберите локальный ZIP и нажмите «Проверить пакет без запуска».
2. Просмотрите название, версию, совместимость, зависимости, список файлов, checksum и запрошенные возможности. Установка не скачивает зависимости.
3. Подтвердите установку. Пакет устанавливается выключенным, без прав; его код не запускается.
4. Откройте пакет. Отдельно выберите каждое разрешение и его области: ключи собственных записей, UUID документов/`new` для создания, определённые локальные каталоги. Изменение прав требует подтверждения. Включение только разрешает последующий явный запуск.

Недоверенный исполняемый модуль работает в ограниченном WebAssembly runtime. Python разрешён только как доверенный код с полным доступом к файлам, сети, командам и данным пользователя. Отдельный процесс и список прав не превращают такой Python в песочницу. Предупреждение привязано к SHA256; обновление пакета сбрасывает доверие и права. Каждый ручной Python-запуск дополнительно подтверждается. Отзыв не отменяет уже совершённые им действия ОС.

## Запуск и внутренние изменения

Заполните объявленные поля, при необходимости выберите конкретные заметки, рукописи или собственные записи расширения. Разрешение чтения не заменяет разрешение записи. Заметки не дают доступа к шаблонам с их разрешениями; память и знания NPC автоматически не передаются.

Нажмите «Вычислить план расширения». Задачу можно остановить. Подготовленный план сам не изменяет JSON. Просмотрите действия и подтвердите перечисленные изменения или отклоните план. Применение внутренних данных и запись результата атомарны; повторное подтверждение не создаёт дубликат. История планов доступна после перезагрузки.

Если исходный документ/права/код/каталог расширений изменились, старый план может быть отклонён. Перечитайте опубликованные права и вычислите новый план. Не пытайтесь вручную перебазировать номер ревизии старого результата. Удаление и повторная установка пакета не оживляют старые разрешения или планы.

## Выбранные внешние файлы

Для передачи файла нужно отдельное `filesystem.read` на существующий локальный каталог вне папки программы/данных и её предков. UNC, сетевые диски, перенаправления/symlink/junction, жёсткие ссылки, устройства и пути с переходами не допускаются. Короткое DOS-имя каталога сопоставляется с полным физическим путём; его подмена или переход за разрешённую область блокируются. Имена с пробелами и кириллицей поддерживаются.

В разделе запуска выберите выданный каталог, введите относительное имя файла и нажмите «Проверить внешний файл». Просмотрите размер, SHA256 и текст, если это UTF-8. Для бинарного файла показываются сведения без текстового просмотра. Подтвердите передачу снимка и добавьте проверенный файл к запуску. До запуска можно убрать его из списка.

Разрешено до8 файлов, максимум128КиБ на файл; все данные и параметры вместе ограничены256КиБ. Если содержимое изменилось после предпросмотра, запуск блокируется: уберите файл, проверьте его снова и подтвердите новый checksum. В плане сохраняются путь/размер/hash прочитанного снимка. Последующее редактирование исходного файла не меняет уже проверенный результат; подтверждение плана не записывает ничего во внешний файл. Эти снимки не добавляются в память NPC автоматически.

## Шаблон из расширения

Действие `tool.template` вызывает сохранённый инструмент-шаблон. Укажите `target` (UUID инструмента), `expected_revision`, `result_id` (UUID новой заметки/главы), `inputs`. Для главы дополнительно нужны `manuscript_id`, `manuscript_revision`, `chapter_title`. Обязательны отдельные grants `tools.run` на точный UUID инструмента (wildcard здесь не выполняет роль выбора), а также `notes.write/new` для заметки или `books.write` на конкретную рукопись. Внутри самого шаблона должно оставаться разрешение notes.write либо manuscripts.write.

Запустите вычисление обычной кнопкой расширения. План показывает заголовок, фактический текст и назначение результата. До подтверждения новая заметка/глава отсутствует; после подтверждения все изменения плана и receipt записываются атомарно. Изменение инструмента, его прав, рукописи или прав плагина делает старый план неприменимым; его можно отклонить и вычислить новый. Повтор подтверждения уже применённого плана не создаёт копию. Текст отображается как текст, HTML из переменных не исполняется.

Декларативный JSON использует существующие подстановки объявленных полей расширения: для передачи пользовательского текста объявите поле и используйте его placeholder в inputs. Значение поля не проходит рекурсивную подстановку. WASM возвращает типизированный план непосредственно. Внешние команды/запись/сеть и правила/планировщик остаются отдельной незавершённой работой; наличие соответствующего grant не выполняет отсутствующую операцию.

## Генератор имён из расширения

Действие `tool.names` содержит `target` (UUID генератора), `expected_revision`, `seed`, `count` (1–100) и `result_id` (UUID записи результата). Нужен tools.run на этот точный UUID, генератор должен оставаться активным. Набор имён вычисляется прежним алгоритмом SHA256-counter и показывается до подтверждения; одинаковые настройки/seed/count дают тот же набор, что обычная кнопка генератора. После подтверждения создаётся tool_run и receipt плана, без записи в заметки, книги, память или собственную область плагина. Для таких изменений нужны отдельные типизированные действия и права. Повтор применения не создаёт дополнительную запись; изменение генератора/прав блокирует устаревший план.


## Внешняя команда и автоматизация — фактическая граница

Действие `command.exec` допускается только для точного локального executable, SHA-256, аргументов и ограниченного времени. Его план отображается до исполнения и требует **отдельного** подтверждения полного доступа. Обычное «применить JSON-план» внешнюю команду не запускает. Возврат из процесса, тайм-аут или отмена не являются гарантией отсутствия внешнего эффекта; после аварии исход помечается неизвестным, повторное выполнение запрещено без ручной сверки. См. [внешние эффекты](PLUGIN_EXTERNAL_EFFECTS.md).

В **Автоматизации** можно создать правило, связанное с определённой ревизией и набором прав декларативного/WASM-расширения. Интервальный триггер работает только при работающем приложении, не как отдельный сервис. Он готовит проверяемый план; применение JSON-изменений и запуск команд по-прежнему требуют подтверждений. Повтор одного и того же события не должен создавать повторный job; отзыв разрешений блокирует последующие попытки. Доверенный `trusted_python` нельзя ставить на автоматический запуск.

Пока отдельные `filesystem.write`, `network.request` и композиция внешних эффектов не испытаны как безопасные готовые функции, нельзя обещать их выполнение только по наличию capability в манифесте.
