# Контракт этапа12 — медиа, сцена и локальные изображения

REQ-ID MED-001–009, CHR-006, UI-007/009/011, NFR-005/006, части COMP/STOR. Допуск01–16 действует, D-06/10/13 сохранены. Этап11:159 backend/10 browser Linux PASS, Windows CI11 ожидается. Контракт до реализации не является объявлением готовности.

Медиа — неизменяемые отдельные файлы по checksum; метаданные/теги/происхождение — JSON. Существующие PNG-портреты совместимы. Планируемые форматы: PNG/JPEG/WebP/GIF/APNG и WAV/MP3/Ogg/FLAC; активные SVG/HTML/исполняемые файлы не обслуживаются как визуальные ресурсы. Изображения полностью декодируются с ограничениями pixels/frames/decoded bytes; аудио проверяется структурным парсером и браузером, без утверждения побитовой декодируемости любого испорченного потока. Файлы проверяются по сигнатуре/содержимому, не только расширению/MIME. Лимиты фиксируются перед измерениями в тестах, не объявляются аппаратным SLA.

Галерея: импорт/поиск/теги/метаданные/предпросмотр/архивирование. Привязки к NPC/сцене/событию/миру и композиции находятся в branch snapshot. Ресурсы общие и неизменяемы; редактирование метаданных библиотеки не переписывает сюжетные ветви. Исторические ссылки остаются доступными после архивирования в галерее. Сцена: упорядоченные слои, фон/NPC, костюм/поза/эмоция, положение/размер/прозрачность, свет/эффекты/переход; музыка/окружение отдельно, общий low-effects/economy. Медиаданные не меняют текст/факты истории; полное отключение визуальных/аудиослоёв сохраняет литературный чат. Воспроизведение аудио запускается явным действием при запрете autoplay браузером.

Собственный ZIP истории должен переносить используемые слои/варианты/аудио и все исторические привязки, проверять checksum/сигнатуры/ссылки без обхода путей. Не создавать неполный пакет при ошибке или превышении размера. Автосохранение редактора отделено от публикации состава сцены.

Внешний image-engine подключается только вручную по loopback; адаптеры проверяют capabilities и используют единую очередь. Не загружать/выгружать/скачивать модели LM Studio. Предварительный API-анализ кандидата ComfyUI: современный endpoint POST /api/jobs/{job_id}/cancel имеет атомарную адресную отмену, POST /prompt принимает клиентский UUID; старый глобальный /interrupt не подходит для безопасной отмены чужих задач. Совместимость ещё требует технических испытаний. Не объявлять ComfyUI официально выбранным движком/конфигурацией без аппаратного сравнения и ресурсов. Engine/веса отдельно устанавливает владелец; приложение не поставляет его внутреннюю БД/плагины или модели. Первичные данные Таверны остаются JSON.

Ресурсный контроль: image-запросы сериализованы с тяжёлыми задачами общей очередью; загруженная LLM остаётся в VRAM. Capability/free-VRAM snapshot — подсказка, не гарантия отсутствия OOM. Нужны понятные ошибки offline/OOM/invalid workflow/cancel/timeout и адресная отмена только собственной задачи. Неопределённый внешний результат после сбоя должен сохранять external job ID и требовать reconciliation до повторного GPU-действия; нельзя считать потерю HTTP-соединения отменой engine-задачи.

BLOCKED до оборудования: выбор production engine/configuration на Windows11/RTX5070 при уже загруженной LLM, измерения VRAM/скорости/качества/OOM и реальная отмена. Эти критерии остаются в матрице; mock-transport проверяет только контракт. Независимые импорт/галерея/композиция/аудио проверяются доступными unit/API/browser средствами, не имитируют генерацию изображения.
