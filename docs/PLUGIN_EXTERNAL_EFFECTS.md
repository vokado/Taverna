# Внешние эффекты плагинов: контракт подключения

2026-11-17. Статус PARTIAL_IMPLEMENTED: отдельный owner-confirmed `command.exec` с долговечным журналом и восстановлением уже подключён и проверен. Множественные/смешанные внешние действия, filesystem.write, network.request, rules/macros/scheduler ещё не реализованы полностью. PLG-003/SEC-006/AUTO-004–005, автономный допуск01–16/D-04.

Используются существующие PluginService, plugin_preview в JSON storage и общая JobQueue. Отдельный supervisor, runtime, очередь и универсальный workflow framework не требуются. Kernel запускается фиксированным backend bridge в существующем host; исполняемый файл имеет полный OS доступ пользователя, не ограниченный остальными правами WASM. Публичный запуск нельзя подключать до проверок ниже.

## Предпросмотр и полномочия

План команды типизирован: executable, argv, timeout. Сервер проверяет актуальные plugin/catalog revision, package SHA и permission epoch; нужен точный commands.exec scope и explicit full-access warning acknowledgement. Путь/hash считывается безопасным открытием после проверки прав. UI показывает точный executable, SHA256, аргументы по отдельности, срок исполнения и предупреждение о полном доступе. Предпросмотр хранит snapshot команды и fingerprint; owner подтверждает именно этот fingerprint и revision. Общая кнопка принятия внутреннего JSON-плана не должна выполнять внешнюю команду.

Первое подключение испытывается с отдельным внешним действием в отдельном плане. Это промежуточная граница реализации, не объявление окончательного сокращения макросов/композиции действий. Перед закрытием14 обязательны проверка исходного объёма и сценариев нескольких действий; их нельзя молча объявить неприменимыми. Для смешанного workflow явно разделяются необратимые внешние действия и атомарные внутренние изменения; общей транзакции между ОС и JSON не обещается.

## Долговечный результат

1. Сохранённый pending preview сам не выполняет эффект. Запрос owner с отдельным подтверждением ставит plugin_effect в существующую очередь с серверным стабильным idempotency key, привязанным к preview. Повтор запроса возвращает тот же job/receipt, даже при разных клиентских ключах.
2. Handler повторно проверяет identity, scopes, код пакета, fingerprint и source guards. До любого запуска сохраняет started, job ID и зафиксированную команду под CAS preview. Недостаток места/ошибка storage до started запрещает запуск.
3. Обычный exit с полностью прочитанными streams фиксируется как наблюдённое завершение процесса с return_code. Ноль не доказывает бизнес-результат произвольной программы. Ненулевой exit не доказывает отсутствие изменений.
4. Cancel, timeout, output_limit, потеря host/backend, неопределённая ошибка либо ошибка сохранения результата оставляют unknown или started, подлежащий преобразованию в unknown при восстановлении. Никакого автоматического повтора команды.
5. После started запись результата разрешена независимо от последующего отзыва plugin grant: это фиксация уже совершённого действия, а не новое полномочие. Новые команды/внутренние изменения после отзыва запрещены. Сохранение outcome CAS-guarded по самому receipt; оно не должно теряться из-за stale source revision.
6. Startup recovery и просмотр истории сопоставляют started с durable job state; interrupted/failed/unavailable outcome требует сверки, не replay. Активный job нельзя принять за умерший при обычном обновлении страницы. Durable job ID ищется через существующую idempotency запись, без полного сканирования очереди на каждый запрос.
7. Owner видит started/unknown и может остановить активный процесс либо отдельно подтвердить результат ручной сверки. Reconcile не запускает команду и сохраняет who/when/reason/outcome. Отклонение pending не выполняет эффект; reject running не маскирует уже начатую операцию. Повтор после сверки требует нового явно подтверждённого действия.

## Очередь, приватность, восстановление

plugin_effect использует существующую bounded queue и foreground reserve. Необратимое действие не получает автоматический preempt-and-replay. Ограниченный срок каждого OS запуска сохраняется; несколько шагов не должны удерживать foreground без предела. Выход, аргументы и пользовательские секреты — локальные owner данные; stdout/headers/tokens не печатаются в общий лог/CI и не добавляются в NPC память автоматически. Программа не управляет моделями LM Studio через этот механизм и не генерирует lifecycle команды.

## Обязательные проверки подключения

- Нет эффекта при отсутствии любого подтверждения/права, неверном fingerprint, stale identity/source, generic internal accept или ошибке записи started.
- Реальный executable/argv/hash, source and frozen Windows; batch/links/hardlinks/drive remap, changed executable before launch, bounded binary output и addressed cancellation.
- Два одновременных подтверждения и повтор после перезапуска дают один OS запуск; side-effect counter хранится в настоящем внешнем файле теста.
- Реальные process kills до started, после started/до запуска, после внешнего эффекта/до receipt и после receipt. Unknown не повторяется, event/job IDs и результат сохраняются.
- Revoke/delete/upgrade во время ожидания/работы; результат не записывается в другую ветвь/ревизию и новые полномочия не появляются.
- Foreground reserve, очередь заполнена, shutdown, диск full/ошибка outcome commit, ручная сверка и видимые кнопки/формы.
- Матрица181 требований и docs обновлены; PASS только для реально выполненной проверки. Linux/fixtures не подтверждают Windows family/реальный LM Studio/RTX5070/генератор изображений.


## Реализованная контрольная точка: одна внешняя команда

Командное действие теперь входит в типизированный PluginPlan v1: `command.exec` содержит абсолютный путь локального executable, SHA256, отдельные argv и timeout 0.1–20с. Публикация такого плана не выполняет команду. Нельзя смешивать команду с JSON-эффектами или другой командой внутри того же плана: этот случай пока явно отклоняется (`plugin_external_mixed`), не объявляется поддержанным.

Предпросмотр проверяет точный `commands.exec` grant, согласие на полный доступ и хеш файла. В интерфейсе доступны путь, хеш, аргументы и отдельная кнопка запуска с подтверждением риска. Обычный `/accept` не исполняет внешние команды. Отдельный API `/previews/{id}/execute-command` ставит задание `plugin_effect` с неизменным серверным ключом идемпотентности; повтор подтверждения возвращает существующее задание, не создавая новый OS запуск.

Перед запуском команда ещё раз проверяется, а в JSON атомарно фиксируется `started` с ID задачи и исходным fingerprint. Реальное исполнение идёт через уже испытанный managed PluginHost с точным argv, без shell. При наблюдённом завершении записывается `observed` с return_code, что само по себе не доказывает успех бизнес-операции; timeout/cancel/сбой приводят к `unknown`. Запись наблюдения не блокируется последующим отзывом полномочий. При перезапуске `started` с завершённой/прерванной задачей переводится в `unknown`, без replay. Пользователь может отметить сверку через `/reconcile-command`, причина и заявленный исход сохраняются как ручное свидетельство.
