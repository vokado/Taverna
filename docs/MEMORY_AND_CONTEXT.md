# Контракт памяти и знаний — этап 08

REQ-ID: MEM-001–007, CTX-001/003–009, DIR-006 (подготовка), CHAT-005/006, STOR-009. D-08/09/10/11 утверждены. Этот документ фиксирует контракт до реализации; статус определяется reports/STATUS.md, не описанием API.

Запись MemoryRecord v1 имеет UUID, story_id/branch_id, version, уровень operational/episodic/personal/relationship/world/plot, тип fact/observation/report/rumor/belief/secret/summary, текст, subject_ids, knower_ids, confidence/salience, статус active/archived/superseded/deleted, pinned, источники и их хеши, происхождение, время/локацию, claim_key, историю изменений. Relationship дополнительно хранит участников, числовые показатели, эпизоды и историю; данные входят в scoped immutable state snapshot. Удаление — логическая версия, не уничтожение исходных сообщений/предыдущих состояний. Версия записи и branch expected_revision проверяются вместе. Изменение/удаление сообщения создаёт альтернативу без старых последствий; fork переносит scope и исходные ссылки, а не знания из будущего.

Доступ к записи проверяется до поиска, embeddings и сериализации prompt: точные story/branch, активность, явный knower, валидность источников; сводки требуют доступа ко всем зависимым фактам и совпадения их версий. Истина мира сама по себе никого не делает знающим. Модель извлекает предложения из видимых выбранному NPC сообщений, не записывает состояние. Объективные/личные/слуховые данные различаются типом и уверенностью. Ручная передача знаний требует явного действия владельца с причиной; автоматическая проверка присутствия не заменяет явно заданное пользователем знание вне сцены.

Предложения модели имеют base_revision, source_hashes и фиксированного владельца знания, требуют preview/подтверждения. Автоматические задачи используют общую очередь с меньшим приоритетом; выключение/отсутствие выбранной загруженной модели не заменяется фиктивным извлечением. Повторы защищены idempotency. Поздний результат не применяется к изменённой ветви. Конфликты по claim_key/субъектам/общим знающим показываются и разрешаются явно: сохранить обе версии либо выбрать действующую, сохранив историю. Разные убеждения разных NPC допустимы.

Индексы — производные JSON, без SQLite/бинарной СУБД. Источник — scoped state/messages; index можно удалить и пересоздать. Embedding cache ключуется моделью/конфигурацией/текстовым хешем; смена модели не переиспользует прежние вектора. При недоступности embeddings остаётся настоящий текстовый поиск с фильтрами и явным сообщением. Исходные секреты не попадают в поиск другого NPC. Формат и реализация индекса проверяются нагрузочным тестом10k, а не обещанным SLA.

API пространства истории: memories CRUD/archive/search/timeline/conflicts, relationships, proposals extract/summarize/review, memory settings/index/export/import. Пакет памяти содержит версию, происхождение и отображение ID; импорт — preview, проверка scope/knowers/source mapping и явное подтверждение. Автозабывание архивирует низкоприоритетные незакреплённые записи по политике и игровым/сюжетным событиям, сохраняя первоисточник. Время/эпизоды/причины связаны ID, календарь мира подключается в09.

Ошибки: invalid_memory, memory_missing, source_missing/source_changed, memory_version_conflict, memory_conflict, knowledge_scope, stale_proposal, invalid_memory_package, embeddings_unavailable; сообщения по-русски. Новые записи v1 не требуют преобразования исходных чатов; старые произвольные memory поля сохраняются, но не получают автоматический статус валидной записи. Контрактные/негативные тесты: секрет через факт/сводку/отношение/поиск, независимые ветви, конфликт версии, invalidation/edit/fork, roundtrip, реальное извлечение с тестовым транспортом, отсутствие дублирования, fallback, cache/model invalidation, rebuild10k. Реальная embedding-модель и LM Studio отдельно BLOCKED до оборудования.

Реализация: knowledge.py, memory.py/memory_ai.py/memory_api.py/memory_io.py/memory_index.py/memory_search.py, MemoryPanel/MemoryResults/useMemoryDraft. Автоматическое извлечение создаёт предложения с ручным подтверждением, а не молчаливую запись модельных фактов. Проверка графа зависимостей итеративная, включает эпизоды отношений и циклы. NPC-представление исключает историю версий, приватные extras/происхождение и неизвестные источники; владелец редактирует полную запись отдельно. Закрепление защищает также транзитивные источники.

Производный JSON-индекс разбит на части по256 записей; перед текстовым сравнением/embedding проверяется доступ. Embeddings проверяются на конечность, размерность и порядок; смена модели/конфигурации разделяет cache. Если движок не раскрывает замену файла под тем же ID, доступен явный сброс эпохи кеша. Это не объявлено автоматическим распознаванием любой замены модели. Приоритетная очередь резервирует места для основного ответа и прерывает вспомогательные задачи.

Редактор сохраняет несколько независимых черновиков с CAS, включая незавершённый JSON и политику; невалидный JSON не публикуется. Импорт требует явного отображения акторов/источников и preview, сохраняет исходное происхождение, отклоняет изменённое отображение повторного пакета. Исходные сообщения и неизвестные старые поля не удаляются. Модельная уверенность — самооценка, не доказанная вероятность истинности. Календарь/события мира подключаются в09, режиссёр — в10; реальные семантические испытания пока BLOCKED.
