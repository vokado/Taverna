# Руководство пользователя «Таверны» 1.0

**Статус документа:** руководство для текущей портативной кандидатной сборки; официальный выпуск 1.0 ещё не принят. Перед передачей пользователю сверяйте с `reports/STATUS.md`, результатами CI и финальной приёмкой. Этот текст не заменяет проверку на целевой Windows с настоящим LM Studio.

## 1. Назначение и требования

«Таверна» — русскоязычная локальная среда персонажей, интерактивных историй и литературного творчества. В интерфейсе можно создавать карточки персонажей, вести чаты, управлять памятью, мирами и сценами, экспортировать рукописи, подключать разрешённые расширения и делать локальные резервные копии.

Основная система — Windows x64. Портативная версия запускается из папки, без установки системного Python/Node. LM Studio устанавливается и запускается пользователем отдельно; саму модель загружает **только LM Studio**, а не «Таверна». Интернет для локального диалога не требуется. Возможности локального генератора изображений и аппаратная производительность зависят от отдельно установленного движка и ещё требуют испытаний.

## 2. Первый запуск

1. Из доверенного источника получите **полный ZIP релиза** и, если опубликована, сверьте SHA256. Не используйте ZIP исходников вместо программы.
2. Распакуйте архив полностью в обычную локальную папку Windows, в которую есть право записи. Для начала лучше использовать отдельный каталог, например `D:\Taverna\`.
3. Запустите `Taverna.exe`. Программа должна поднять локальный сервер только на `127.0.0.1` и открыть браузер; не нужно самостоятельно настраивать веб-сервер.
4. Если запуск не удался, откройте `Taverna-Diagnostics.exe` для локальной диагностики. Не передавайте посторонним журналы с личными данными без предварительного просмотра.
5. Завершайте приложение штатной кнопкой «Завершить приложение». Простое закрытие браузерной вкладки не обязательно останавливает локальный сервер.

Файлы пользовательских данных, истории, материалы, расширения и резервные копии находятся в переносимой папке приложения. **Не запускайте два отдельных экземпляра над одной и той же папкой данных.** Не меняйте системные JSON-файлы вручную, пока программа работает.

## 3. Подключение LM Studio

1. Запустите LM Studio и вручную загрузите выбранную локальную модель.
2. Запустите локальный сервер LM Studio. Стандартная конечная точка: `http://127.0.0.1:1234`. Используйте точный адрес и порт вашей настройки.
3. В «Таверне» откройте **Рабочее пространство**, укажите адрес и выполните проверку подключения.
4. Выберите **уже загруженную** модель из доступного каталога. Если модели нет, проверьте её состояние в LM Studio.
5. Перед первым большим диалогом отправьте короткий проверочный запрос; убедитесь, что поток ответа и отмена работают.

«Таверна» не должна самостоятельно скачивать, загружать или выгружать модели. Если внешний API LM Studio не отвечает, сначала проверьте адрес, сервер и состояние модели. Ошибка соединения не означает потерю сохранённых историй. Подробнее: [LM Studio](LM_STUDIO.md).

## 4. Разделы интерфейса

| Раздел | Для чего нужен |
|---|---|
| Главная | Состояние программы и обзор локальных данных |
| Рабочее пространство | Локальный сервер, модели и параметры подключения |
| Персонажи | Создание/редактирование карточек и обмен совместимыми форматами |
| Истории | Чаты, сцены, участники, альтернативные ветви и сохранения |
| Профили и промпты | Параметры контекста, порядок инструкций, предпросмотр |
| Миры и сценарии | Сюжетные миры, события, правила, календарь и знания |
| Медиабиблиотека | Портреты, сцены, звуки, слои и локальные ресурсы |
| Литературный редактор | Рукописи, структурирование, экспорт и версии |
| Материалы и инструменты | Заметки, закладки, словари, шаблоны, генераторы |
| Расширения | Проверка пакета, разрешения, запуск, планы и результаты |
| Автоматизация | Ручные макросы, интервальные правила, история запусков |
| Резервные копии | Создание, проверка, скачивание архивов и диагностики |
| Настройки | Внешний вид, режимы интерфейса и локальные параметры |

В каждом разделе используйте сначала просмотр, затем сохранение. При сообщении о конфликте ревизии **обновите данные**, сравните изменения и повторите действие осознанно: не пытайтесь принудительно перезаписать данные другой вкладки.

## 5. Персонажи, истории и ветви

Создайте персонажа или импортируйте карточку в поддерживаемом SillyTavern PNG/JSON формате. При импорте просмотрите предпросмотр и предупреждения совместимости; незнакомые поля должны сохраняться в доступном исходном представлении, но не все нестандартные расширения сторонних карточек гарантированно исполняются.

Создайте историю, выберите персонажей и при необходимости мир. В чате сообщения принадлежат конкретной истории и ветви, а не общему глобальному диалогу. Повторная генерация и правка прошлого создают альтернативу; исходная ветвь не должна уничтожаться. Для возврата используйте переключение ветви или именованный checkpoint. Проверяйте участников сцены и точку ветвления перед длинной генерацией.

Отдельные игровые/сюжетные знания, отношения, память и RPG-состояние ветвей должны быть изолированы. Не используйте экспорт одной ветви как основание для перезаписи других без просмотра. Подробнее: [чаты и ветви](CHAT_AND_BRANCHES.md), [память](MEMORY_AND_CONTEXT.md), [миры](WORLDS_AND_EVENTS.md), [режиссёр и NPC](DIRECTOR_AND_NPC.md).

## 6. Контекст и память

Профиль задаёт правила сборки промпта, ограничения длины и управление контекстом. Сначала просмотрите фактический собранный контекст и только затем запускайте длинный сюжет. Оценки токенов могут быть приблизительными: точные цифры зависят от внешней модели и доступных метрик LM Studio.

Сводки, факты мира, отношения и знания NPC требуют внимательной проверки. То, что знает один NPC или одна сюжетная ветвь, не должно автоматически становиться известно всем. Для проверки используйте редакторы знаний и инспектор источников. Возврат к прежней точке истории должен восстановить знания, существовавшие на тот момент, а не будущие события.

## 7. Медиа, RPG и литературный редактор

Медиабиблиотека хранит локальные файлы и варианты ресурсов. До генерации изображений проверьте наличие совместимого локального генератора и свободные ресурсы видеокарты. Не полагайтесь на произвольное одновременное размещение модели LM Studio и генератора изображений в VRAM: окончательная проверка зависит от оборудования.

RPG-подсистема является **необязательной** частью истории. Если она включена, игровые изменения и броски должны публиковаться в текущей ветви и не изменять другие сюжетные линии. Литературный редактор поддерживает работу с рукописями и несколько форматов экспорта. После экспорта EPUB/другого формата откройте файл в независимой программе и проверьте оглавление, форматирование, изображения и кириллицу.

Справка: [RPG](RPG.md), [медиа](MEDIA_AND_IMAGES.md), [литературный редактор](LITERARY_EDITOR.md).

## 8. Расширения: принцип наименьших прав

Не устанавливайте неизвестное расширение, не просмотрев ZIP-пакет, список файлов, запрошенные разрешения и его происхождение. Установка сама по себе не предоставляет прав. Включайте только необходимые отдельные области.

Недоверенный WASM работает с ограниченными возможностями. **Доверенный Python-плагин имеет полный доступ к компьютеру**: отдельный процесс не делает его безопасным. Точно разрешённые внешние программы также могут выполнить необратимые действия. Проверка плана и отдельное подтверждение нужны до запуска.

Не путайте «вычислить план» и «применить изменения». Вычисление не означает сохранение данных. Повтор одного подтверждения не должен вызывать второй внешний эффект. Если исход операции неизвестен после сбоя, сначала проверьте результат вручную, **не запускайте команду повторно наугад**. Подробнее: [плагины](PLUGIN_GUIDE.md), [безопасность](PLUGIN_SECURITY.md).

## 9. Правила и расписания

Во вкладке **Автоматизация** выберите включённое декларативное или WASM-расширение, задайте название, параметры и способ запуска: вручную либо с интервалом. Укажите максимальное число запусков. Интервальные правила работают только пока «Таверна» запущена; это не отдельная фоновая служба Windows.

Расписание готовит **план на просмотр**, а не незаметно исполняет произвольную команду ОС. Изменение прав или версии расширения блокирует ранее закреплённую автоматизацию до повторной проверки. История правил помогает отличить выполненный план от эффекта, который пользователь ещё не подтверждал. Доверенный Python в автоматическом режиме запрещён.

## 10. Резервные копии и восстановление

Перед важными изменениями создайте ручной полный архив в разделе **Резервные копии** и нажмите **Проверить**. Храните хотя бы одну копию на отдельном физическом носителе: автоматические ZIP внутри той же папки не защитят от отказа самого диска. Автоматические копии создаются раз в сутки при работающем приложении, хранение: семь последних и до четырёх недельных; ручные архивы не подлежат автоматическому удалению.

Проверенный ZIP полной копии содержит согласованные JSON-документы и используемые ими локальные ресурсы. Для восстановления **закройте программу** и используйте мастер ручного восстановления из поставки, выбирая **новый, ещё не существующий каталог**. Существующую установку и рабочую папку данных мастер не перезаписывает.

Для обновления используйте `Taverna-Updater.exe` и отдельную новую папку. Старая версия остаётся доступна для отката. При неудачном обновлении просто запускайте старую папку; данные, созданные уже в новой версии, автоматически обратно не объединяются. См. [инструкцию обновления](MANUAL_UPDATE.md), если файл включён в соответствующую сборку.

## 11. Диагностика и приватность

В разделе резервных копий можно скачать **техническую диагностику**: она содержит версии и агрегированные результаты проверки целостности, но по умолчанию не включает истории, промпты, персонажей, медиа или конфигурацию. Дополнительные журналы включаются только отдельным действием пользователя; маскирование сведений в них частичное. Перед передачей архива кому-либо обязательно просмотрите его содержимое.

Никакая функция диагностики не должна самостоятельно отправлять ZIP в интернет. При обращении за помощью передавайте точный код ошибки и краткие шаги воспроизведения, а не всю личную библиотеку.

## 12. Если что-то пошло не так

- Программа не открывается: проверьте, что ZIP распакован полностью, каталог доступен для записи, и нет второго работающего экземпляра. Используйте диагностический запуск.
- LM Studio недоступен: проверьте локальный сервер, порт, каталог загруженных моделей и политику локального брандмауэра.
- Сохранение отклонено: обновите документ, проверьте конфликт ревизий, не пытайтесь обходить защиту.
- Изображение или звук недоступны: проверьте наличие локального файла, его целостность и свободное место.
- Команда плагина завершилась неизвестным исходом: не повторяйте автоматически; сверяйте результат вручную.
- Резервная копия не проверяется: сохраните проблемный ZIP для диагностики, не используйте его вместо заведомо исправной копии.
- После обновления не работает новая версия: закройте её и запускайте **старую** сохранённую папку.

## 13. Граница текущей приёмки

Успешные тесты GitHub Actions на Windows и Ubuntu подтверждают конкретные проверенные сценарии, но **не заменяют** испытание на целевой Windows 11 с локальным LM Studio, Dolphin Mistral Nemo 12B, RTX 5070 и реальной библиотекой пользователя. Пока не закрыты обязательные критерии этапа 16, внутреннюю сборку нельзя выдавать за полноценный принятый релиз 1.0.

Технические подробности: [архитектура](ARCHITECTURE.md), [JSON-хранилище](JSON_STORAGE.md), [сводка разработки](../reports/STATUS.md).
