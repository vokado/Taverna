## Исполнение и границы

Используется Wasmtime50.0.1 (Apache-2.0 WITH LLVM-exception, wheel WindowsAMD64 существует). Недоверенный исполняемый модуль — WebAssembly без WASI и любых imports, отдельный worker, JSON input/output; никакие каталоги, сеть, системные команды или Python не предоставляются гостю. Экспорты ABI v1: memory, alloc(i32)->i32, run(i32,i32)->i64; результат упакован как pointer<<32|byte_length. Ограничиваются исходный модуль, число функций, linear memory/таблицы/stack/fuel, вход/выход и wall deadline. Это не обещание защиты от неизвестного дефекта самого runtime/ОС. Точные испытанные ограничения/версии ведутся вместе с кодом; Linux не подтверждает Windows frozen worker.

Функция возвращает план типизированных действий, не получает прямого storage/OS API. Broker повторно проверяет manifest/grants/code hash/epoch перед чтением и эффектом. Отдельные capabilities: данные приложения/собственная область, разрешённые каталоги чтение/запись, network, tools, commands; scopes/отзыв не смешиваются. Доступ к внешним каталогам и командам требует отдельного разрешения/предпросмотра. Внешняя команда сама исполняется с правами пользователя: это повышение доверия за пределы WASM и требует явного предупреждения/подтверждения точного executable/argv, без обещания ограничить её остальными guest grants. Прямые LM Studio lifecycle операции запрещены, моделью управляет владелец.

Доверенный Python — отдельный процесс с явным предупреждением о полном доступе к файлам, сети, командам и данным пользователя. Manifest scopes не являются ОС-песочницей для Python; отзыв останавливает управляемый host и запрещает новые запуски, не отменяет уже выполненные действия/созданные потомки. Доверие привязано к конкретному checksum и сбрасывается при обновлении. Недоверенный Python не исполняется. Никакой автоматической загрузки dependencies/code из сети или pip install.

Менеджер: bounded ZIP + versioned manifest UUID/version/API compatibility/dependencies/requested capabilities; import preview без исполнения, enable/disable/delete с подтверждением, независимые grants/revoke, dependency/cycle checks. Включение не означает запуск. Shared JSON registry/catalog CAS защищает межплагинные зависимости и конкурентное изменение прав. Restore не включает плагины автоматически.

## Эффекты и автоматизация

Одна JobQueue/EventBus, JSON ledger/outbox/receipts. Модель/модуль предлагает действия; backend валидирует, показывает preview, применяет разрешённое. Внутренний эффект и receipt атомарны; внешний эффект отмечается started до выполнения и при неизвестном исходе требует reconciliation, не слепого replay. Отключение/отзыв во время задачи проверяется до эффекта и публикации; результат старой ревизии/ветви не переносится автоматически.

Правило имеет trigger/condition/action/limits/state/history/disable. Визуальные macros/templates запускают те же проверенные действия. Планировщик подаёт работы в общую очередь, ограничивает частоту/число/цепочку, имеет явную catch-up политику и стабильный event ID. Обслуживание памяти/сводок/индекса использует настоящие существующие обработчики; backup интегрируется с15, не имитируется успешной заглушкой. Не обещать exactly-once произвольной команды. Все обязательные функции остаются в объёме; незавершённая интеграция помечается явно.

Проверки: hostile ZIP/manifest/versions/dependencies, unknown/WASI imports, memory/fuel/timeout/stack/oversize/trap/bad ABI, настоящий subprocess crash и bounded pipes, отсутствие вызовов OS/network из WASM, isolated native worker Windows, trust warning/hash invalidation/revoke race, scope/path/reparse/network/command checks, receipt/idempotency/crash/restart/unknown external outcome, cyclic rules/catch-up/durable event feed/maintenance. Проверки против реальной ОС/движков не подменяются fixtures. До пройденных испытаний соответствующие критерии IMPLEMENTED_UNVERIFIED/NOT_RUN/BLOCKED, не VERIFIED.

## Реализованная точка registry (2026-11-16)

PluginRegistry хранит versioned JSON registration и общий CAS catalog, исходники immutable по SHA256. Управление проверяет ревизию записи, catalog revision и просмотренный checksum. Preview/install/enable никогда не исполняют код. Dependency cycles/missing/incompatible versions блокируют включение; update сбрасывает grants/trust и отключает зависимые. Области файловой системы отвергают UNC/network drives, app root/ancestors/descendants и symlink/junction; lstat проверяет сам reparse point. Чистый валидатор ZIP имён не читает живой каталог.

Worker перед guest устанавливает resource cap512MiB; Windows Job Object также ограничивает family commit/число процессов8 и закрывает обычных потомков при завершении host, проверяя фактическую конфигурацию QueryInformationJobObject. Linux RLIMIT_AS не обеспечивает остановку потомков. Это не песочница для trusted Python: код с полными правами потенциально обходит такие ограничения. Failed enforcement запрещает запуск. Новые native assertions ожидают CI; Linux тесты не подтверждают Windows. SDK позволяет packaged helpers через __file__/entry directory и bundled dependencies, без обещания универсального python.exe.

Registry/UI реализованы, broker/production execution и automation ещё IN_PROGRESS. Полная API выдача прав сама по себе не доказывает применение каждого scope при эффекте. Матрица PLG остаётся NOT_RUN для составных критериев; проверенные подсценарии приведены в tests/test_plugin_registry.py, test_plugin_packages.py, test_plugin_compute.py и e2e/plugins.spec.ts.

## Вычисление и внутренний broker: контракт v1

Перед модулем: PLG-001–005/AUTO-004–005/SEC-006; допуск01–16 действует. Новые API `/plugins/{id}/run`, `/previews`, `/data/{key}`, `/plugins/previews/{id}/accept|reject`. Вход содержит plugin revision, permission epoch, package SHA256 **и catalog revision**, объявленные parameters и явный список reads (`own|note|book`, target, expected_revision). Повтор запроса — Idempotency-Key общей JobQueue; production handler `plugin_compute`, priority20/preemptible, отдельной очереди нет. Trusted Python дополнительно требует подтверждения полного доступа для каждого ручного запуска. Включение пакета не даёт этого подтверждения автоматически.

Чтения выполняются в одном storage view, сначала проверяются scope и текущий пакет. Не передаются произвольные пути/REST URL, полный registry, память NPC, состояния ветвей или невыбранные документы. notes.read не открывает template/name_generator с их grants. Ввод ≤256КиБ; типы полей соответствуют манифесту. WASM/Python получают JSON `{format,parameters,data}`; проверенные bundled Python helpers копируются в отдельный временный снимок, чтобы удаление/обновление пакета не заменило helper после проверки hash. Full-access Python способен обращаться к ОС независимо от входа; это не меняет предупреждение.

Декларативный entry ≤256КиБ — данные, не eval. Подстановка `{{key}}` в строках однопроходная, без повторного исполнения вставленного текста, с общим byte/node/depth budget **до** построения большого результата. Возвращается PluginPlan v1, ≤32 действий/256КиБ. Сейчас выполнены действия `own.set`, `own.delete`, `note.save`, `book.save`; посторонние types отклоняются. notes.write разрешает только заметки/закладки/словари, не создаёт/не перезаписывает генераторы/шаблоны. books.write использует существующий ManuscriptService.plan с версиями и проверкой ссылок/медиа. Scope `new` для создания новых заметок/рукописей, UUID для существующих, own scopes — ключи внутри UUID конкретного плагина. Права чтения и записи независимы.

Вычисление сохраняет **pending preview**, а не данные. Preview содержит исходный план, identity, read/write guards, точные mutation values и metadata. Accept после явного подтверждения проверяет identity и атомарно пишет все внутренние эффекты, версии рукописей и status=applied; повтор того же accept возвращает receipt без повторного эффекта. Reject не применяет изменений и разрешён после отзыва прав. CAS проверяется под storage lock перед публикацией. Read/target revision conflict сохраняет pending preview и остальные данные. Другой плагин, удаление/переустановка или любое изменение catalog делает старый pending preview неактуальным; нужен новый запуск. Это намеренно строгое ограничение для защиты от ABA и изменений зависимостей. Собственное удаление — JSON tombstone с монотонной ревизией, чтобы delete/recreate не оживил старый guard.

Ошибки: plugin_parameters/input_conflict/scope_denied/catalog_conflict/permission_revoked/plan_invalid/output_limit/duplicate_effect/effect_conflict; kernel errors не преобразуются в успех. Job restart использует существующее interrupted/no replay; сохранённый preview/receipt остаётся. Новые исполнения/публикации блокируются stale identity; HTTP disable/revoke отменяет управляемый процесс через ту же очередь. Уже выполненные прямые ОС-эффекты trusted Python не отменяются.

Следующие функции остаются обязательными и IN_PROGRESS: broker для network/filesystem/commands/tools, журнал started/unknown/reconciliation внешних эффектов, rules/macros/scheduler, durable outbox/catch-up/loop budgets и maintenance/backup15. Выданный manifest grant ещё не означает реализованную операцию этого broker. Новые операции не подменены успешными no-op. Новая native end-to-end smoke исполняет WASM через frozen сервер/host/общую очередь и применяет own effect/receipt дважды без дублирования; её Windows результат фиксируется только после CI.

Пользователь: «Расширения» → импорт ZIP и проверка → отдельные права/включение → поля и выбранные источники → «Вычислить план расширения» → просмотр действий → подтверждение JSON-изменений или отказ. Остановка вычисления и восстановление истории планов доступны кнопками. Черновики прав отдельно от опубликованных grants. Источники/параметры запуска не являются NPC-контекстом.

## Следующий модуль: ограниченное чтение внешнего файла

До реализации: PLG-003/SEC-006/AUTO-004, допуск01–16/D-04 действует. Это отдельный building block broker, **не завершение внешних эффектов/automation**. Контракт: явные grant-root + относительное имя, отдельное filesystem.read; каталог должен быть существующим локальным, вне приложения/данных и их предков, без symlink/junction/network drive. Имена поддерживают пробелы/кириллицу, отвергают traversal/ADS/устройства/неоднозначность Windows. Проверяется реальный открытый handle до чтения, regular file/single hardlink, размер128КиБ; bounded read и SHA256, несовпавшая snapshot/stat отклоняется. Никакой записи/команды/network из этого helper. Ошибки не выдают содержимое/нечитаемые пути. Следующие API integration/предпросмотр внешних действий требуют отдельного ledger/подтверждения; их здесь нет. Предел128КиБ инженерный, не аппаратный SLA. Windows handle/reparse проверки требуют Windows CI, Linux не подменяет их.

### Интеграция внешнего чтения: следующий контракт

REQ PLG-003/AUTO-004/SEC-006;14 продолжается. Только выбранные владельцем файлы из опубликованного filesystem.read scope: POST file-preview по pinned identity возвращает hash/size/ограниченный текст; добавление в запуск требует отдельного подтверждения конкретного файла. Run содержит scope/name/ожидаемый SHA256, максимум8 файлов и общий guest input256КиБ. Изменение файла после preview до чтения блокирует запуск. Guest получает snapshot bytes/base64, без OS handle; в pending plan сохраняется provenance path/hash/size. Это снимок прочитанного файла, а не обещание атомарного чтения внешней ФС вместе с JSON. После чтения файл может измениться; owner видит hash исходного snapshot. Apply по-прежнему меняет только внутренние типизированные JSON-документы. Внешняя запись/сеть/команды пока не подключаются. Основные действия доступны формами; сохранённые file snapshots не становятся NPC-памятью автоматически.
