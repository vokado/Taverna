# Контракт этапа11 — необязательные RPG-модули

REQ-ID WORLD-008, части WORLD-005–007, TOOLS-001/003, CTX-001, NFR-002/006. Допуск01–16 действует. Вход10:139 backend/9 browser Linux PASS; повтор Windows CI10 и целевое оборудование отмечаются отдельно. Контракт до реализации не означает PASS функций.

Одна branch-state JSON секция rpg format1; семь переключаемых модулей inventory/stats/skills/dice/economy/conflicts/random_events. По умолчанию все выключены, пустая история не получает RPG-данных или дополнительного prompt. Выключение сохраняет состояние/журнал, исключает отключённые модули из контекста. Участники — NPC истории и постоянный player UUID без обязательного создания персоны. Пользовательские операции выполняются явно через формы; модель не получает нового права записи.

Настройки/каталоги: разрешённые модули и действия мира, допустимые локации/флаги/внесценовые действия; каталог предметов/целочисленных валют, таблицы случайных событий с весами. Ограничения прикреплённого мира из extras.rpg_policy пересекаются с локальной политикой, не обходятся включением модуля. Типы/границы/ссылки валидируются. Ручная коррекция параметров/балансов/инвентаря помечается отдельно от игровых операций. Расходы/перенос/торговля не допускают отрицательных остатков, не создают предметы или деньги, публикуются одним state snapshot. Отключённый вспомогательный UI-модуль не запрещает внутренний RNG проверки навыка; все используемые результаты сохраняются в соответствующей операции.

RNG sha256-counter-v1 использует записанные seed/counter и rejection sampling без modulo bias; фиксирует входы, каждый бросок, суммарный результат и индекс RNG. Повтор event_id с тем же fingerprint возвращает прежний результат, с иным — конфликт. Не является криптографическим протоколом честности против владельца файлов. Ветви/откат восстанавливают seed/counter/results; копия прошлой записи не повторяет эффект. Все primary записи только ChatService/JsonStore CAS/recovery, отдельной очереди/БД нет.

Механики: инвентарь с количеством/переносом; характеристики и здоровье; навыки и проверки d20+attribute+skill против difficulty; отдельные NdS+modifier броски; валютные счета/переводы/обмен предмета на валюту; пошаговый конфликт с инициативой/попаданием/уроном/завершением; взвешенные случайные события с атомарными наградами/изменением параметра. Нет скрытого написания реплик игрока, симуляции несуществующей LLM или бесконечного фонового боя. Непредсказанные/запрещённые действия отвергаются целиком с русской ошибкой, без продвижения RNG/частичных последствий.

Проверки: каждый модуль отдельно/совместно; выключение без потери прозы/состояния; неизвестные UUID/каталоги/нехватка остатков/переполнение/запрещённая мировая политика/мертвый участник/чужой ход; deterministic seed/counter replay; повтор/конфликт/CAS/рестарт/fork/checkpoint; knowledge-own NPC projection; реальные UI-операции и регрессия. Плановые схемы: RpgState/Settings/ActorSheet/DiceRequest/Action/RandomTable; API GET/settings/action с branch+revision+event_id, журнал в GET. Поздняя проверка Windows portable не заменяется Linux. Числовые пределы защищают ресурсы, не являются согласованным игровым балансом или SLA.

## Использование

В истории раскройте «Игровые модули RPG» → «Настройки и каталоги RPG». Включите нужные механики и сохраните настройки. Внутренние броски проверки/инициативы/атаки доступны своему модулю даже при выключенном отдельном интерфейсе кубиков. При выключенных характеристиках и конфликтах прежнее нулевое здоровье не ограничивает независимый инвентарь. Параметры/навыки другого NPC не включаются в контекст; каждому передаются только собственные включённые поля, собственная роль в активном конфликте и последние собственные случайные события. Истории/ветви используют обычные checkpoints и JSON recovery. Старая пустая секция rpg={} читается без миграции; GET не создаёт seed или запись.

В «Предметы и валюты» задайте устойчивый ключ, название, вес в граммах/число десятичных знаков. Счета, цены и передачи — целые минимальные единицы: при decimals=2 значение125 означает1,25. Инвентарь агрегирует одинаковые предметы по ключу. Грузоподъёмность0 снимает предел. Удаление используемого каталога/превышение массы/отрицательный остаток отвергаются целиком. Исправление количества/баланса — отдельное явно журналируемое действие владельца; торговля не чеканит деньги и не создаёт предметы.

Для проверки d20 выберите участника, необязательную существующую характеристику/навык и сложность. Произвольные команды или исполняемые формулы не принимаются. Конфликт начинается явно с минимум двух участников: инициатива d20+agility (если характеристики включены), ничья разрешается по UUID, порядок/ход/раунд сохраняются. Ход: d20+выбранные модификаторы против defense (по умолчанию10), урон NdS+modifier, минимум0. Нулевая цель не атакуется; при одном живом участнике конфликт завершён. В журнале есть полный бросок урона и фактически потерянное здоровье, ограниченное остатком HP. Владелец может завершить конфликт отдельно, с причиной; приложение не генерирует реплики игрока или бесконечный автобой.

Таблица случайных событий содержит именованные исходы с целыми положительными весами. Формы создают исходы и необязательное последствие; экспертный JSON поддерживает до16 последствий одного исхода. Последствия: предмет/валюта/здоровье/характеристика выбранного участника, с теми же проверками модулей/остатков/пределов. Если последствие запрещено, первичное состояние и RNG не меняются. Включение random_events не даёт прав на отключённый инвентарь/экономику/характеристики. Событие сохраняется отдельно от прозы с участниками и ссылкой на квитанцию, а его текст поступает только выбранному NPC.

Локальная политика RPG и ограничения шаблона мира extras.rpg_policy пересекаются. Формы задают разрешённые модули, внесценовое действие, конкретные локации, запрещённых участников и обязательные флаги; отсутствие списка локаций означает отсутствие дополнительного ограничения. При наличии rpg_policy в прикреплённом мире его значения также обязательны. Неизвестная/невалидная политика не игнорируется. Присутствие и флаги проверяются в том же branch snapshot, что и ожидаемая ревизия. Модель/режиссёр не получили интерфейса изменения RPG — доступные операции выполняются владельцем кнопками.

«Журнал игровых операций» хранит before/after, параметры, исход, seed/counter/draws и алгоритм. Повтор event_id не выполняет операцию заново. Новый seed задаётся явно в настройках, обнуляет счётчик и сохраняет прежние значения в журнале. Fork восстанавливает состояние/seed/counter своего эпизода; журнал предка остаётся происхождением, а новые записи принадлежат новой ветви. Аудит/участники/конфликты проверяются при импорте собственного ZIP истории. Чужая подпись или криптографическая честность владельца файлов не заявляется.

Правки настроек и незавершённый JSON автосохраняются в отдельных черновиках, включая невалидные числовые поля. Основное состояние принимает только полную схему. Публикация формы сохраняет отдельно оставшийся экспертный raw-черновик; конфликт версии не приводит к автоматическому переписыванию чужих данных. Есть восстановление/отдельная копия черновика. Закрытая панель не загружает весь журнал до раскрытия.
