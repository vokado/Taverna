# Персонажи и совместимость карточек

Статус внутренней разработки. Реализованы локальные JSON/PNG V1/V2/V3 adapters и собственный пакет `taverna-character-1` (.tavcharacter). Это не обещание совместимости с любым сторонним расширением.

## Источники форматов

Изучены 2026-11-15: https://github.com/malfoyslastname/character-card-spec-v2/blob/main/spec_v2.md (включает определение V1) и https://github.com/kwaroran/character-card-spec-v3/blob/main/SPEC_V3.md. Тексты скачаны для анализа в scratch, не включены в поставку как материалы с непроверенной лицензией. В этих репозиториях не найден корпус реальных пользовательских карт; обязательная COMP-006/QA-007 проверка на независимом реальном корпусе остаётся BLOCKED до законно доступных fixtures. Собственные синтетические карты не выдаются за реальные.

V1: шесть базовых строк. V2/V3: соответствующий spec и data; неизвестные поля data/extensions и исходные top-level metadata сохраняются. Изменения имени не меняют UUID. Версии, отличающиеся от 2.0/3.0 в знакомом spec, принимаются с предупреждением; неизвестный spec отклоняется. Полная стандартная семантика prompt/lore/приветствий реализуется в зависимых 06–09; чтение полей не означает, что все они уже влияют на генерацию.

PNG/APNG: CRC/структура/IEND/лимиты/декодирование проверяются, metadata tEXt chara/ccv3 base64 UTF-8 JSON; ccv3 имеет приоритет, дубли известных ключей отклоняются. При PNG export старые card chunks заменяются, прочие chunks (включая неизвестные metadata) сохраняются. Без портрета создаётся нейтральный PNG-контейнер с настоящими данными карточки; это не генерация изображения. Поддержка CHARX/внешних assets URI не заявляется; внешние URI автоматически не скачиваются и не исполняются.

## Отчёт экспорта и собственный пакет

Сначала preview report, затем явное скачивание. V3-only поля перечисляются при V2/V1 конвертации, собственные taverna поля перечисляются как неподдерживаемые стандартным форматом. «Неподдерживаемый» означает отсутствие стандартной семантики, не обязательно удаление каждого неизвестного vendor-поля: при экспорте в исходную версию оно сохраняется. Для полного сохранения всех собственных полей выбирается .tavcharacter.

Пакет: character.json + assets/portrait.png (при наличии) + manifest.json с SHA-256 каждого файла. При импорте UUID карточки/медиа создаются заново, привязки remap; история/отношения прохождения не смешиваются с базовой карточкой. Неподдерживаемые assets в пакете пока отклоняются явно, не теряются молча; полный мультимедийный пакет расширяется в 12/15. Отсутствующий привязанный портрет блокирует lossless package export с понятной ошибкой. Zip-slip, дубли имён, encrypted entries, oversized/decompressed size отклоняются до записи; текст не исполняется.

## Редактирование

Пошаговый мастер и полный JSON-редактор работают с одним payload. Системные/исторические prompts, metadata/sections/extensions доступны без скрытого удаления. Портрет импортируется из PNG; выражения/костюмы/анимации и их применение — 12. Три режима характера сохраняются и объясняются, enforcement развития по истории — 10. Группы/состояния и явный перенос событий — 06–10, пока не объявлены завершёнными.

Публикация в библиотеку явная; редактируемые черновики автоматически сохраняются в JSON отдельно, включая невалидный raw JSON. После reload можно восстановить draft с исходной expected_revision, не перезаписав чужую правку. Во время явного сохранения поля заблокированы, неприменённый expert JSON нельзя молча заменить старой версией. При выходе есть предупреждение о неопубликованных изменениях. Drafts не хранятся в browser localStorage; браузер держит лишь текущую рабочую копию.

ИИ-помощник использует настоящий LLM queue adapter: create/биография/примеры/поиск противоречий. Ответ можно править, валидировать и принять в draft, отдельное сохранение публикует его. Model output никогда не пишет карточку напрямую. Live LM Studio здесь недоступен: UI/код помощника реализованы, качество/совместимость конкретной модели НЕ подтверждены.
