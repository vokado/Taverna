# HTTP API «Таверны» — локальный контракт

Действует для внутренней кандидатной версии 1.0. **Не** является стабильным публичным API. Все запросы по умолчанию идут только на `127.0.0.1` и защищены сессией запуска. Никакого облака, внешней авторизации, прокси или удалённого прослушивания нет.

## Главный источник схемы

Актуальная схема автоматически собирается FastAPI при запуске: **`GET /api/v1/openapi.json`**. Её нужно читать в уже авторизованной локальной сессии. Стандартные публичные Swagger/Redoc URL намеренно отключены. Не копируйте bootstrap URL или cookies в переписку, отчёты или команды. Если документация в файле расходится с машинной схемой, проверяйте версию приложения и фактическую реализацию конкретной сборки.

## Сеанс и защита

- `GET /api/v1/health` — ограниченная информация о готовности слушателя.
- `POST /api/v1/session/bootstrap` — обмен одноразового токена из URL запуска на HttpOnly + SameSite=Strict cookie; ответ выдаёт CSRF.
- `GET /api/v1/session` — проверка текущей сессии, выдача CSRF для клиентского кода.
- Все изменяющие методы (`POST`, `PATCH`, `PUT`, `DELETE`) должны передавать `X-Taverna-CSRF`. Внутренние API предназначены для фронтенда и локальных проверок, не для внешнего сетевого управления.
- Отсутствие действующей сессии: HTTP 401; нарушение CSRF или области прав: 403; конфликт ожидаемой ревизии: 409; некорректная форма: 422; недоступный компонент может возвращать 503.

Ошибки возвращают JSON с машинным `code`, русским `message_ru`, идентификатором запроса `request_id`, `recoverable` и обезличенными `details`. **Не** выводите в журналы полный HTTP body, токены, приватные документы, полный prompt, содержимое изображений.

## Основные маршруты и подсистемы

| Область | Примеры |
|---|---|
| Статус и управление | `/api/v1/status`, `/api/v1/capabilities`, `/api/v1/system/shutdown` |
| Подключение и генерация | `/api/v1/models`, `/api/v1/generations`; асинхронные jobs/events/SSE |
| Персонажи | `/api/v1/characters`; редакции, импорт/экспорт карточек |
| Истории | `/api/v1/stories`; сцены, сообщения, ветвление, восстановление |
| Память и знания | маршруты `/api/v1/memory` и связанные API истории |
| Миры и события | `/api/v1/worlds`, сценарии, события и календарь |
| Медиа | `/api/v1/media`; проверка форматов и локальные файлы |
| Рукописи/материалы | `/api/v1/manuscripts`, `/api/v1/tools` |
| Расширения | `/api/v1/plugins`; установка, права, вычисление/применение плана |
| Автоматизация | `/api/v1/automations`; правила, запуск с ключом, история |
| Архивы | `/api/v1/backups`, `/api/v1/diagnostics/archive` |
| Проверка хранилища | `/api/v1/diagnostics/storage`, `/api/v1/storage/integrity-check` |

Фактические HTTP-методы, поля и схемы **следует брать из OpenAPI именно проверяемого коммита**, а не из таблицы выше: часть специальных маршрутов входит в вложенные роутеры и может меняться до официального выпуска.

## Ревизии и идемпотентность

Сохранение JSON требует `expected_revision`; конфликт означает, что документ был изменён после чтения. Клиент должен получить свежую версию, сравнить и предложить повтор, а не тихо затирать другого владельца вкладки. Для генерации, выполнения плагинов и отдельных операций автоматизации используется `Idempotency-Key`: повтор того же запроса возвращает существующую задачу, а чужой payload с тем же ключом вызывает конфликт.

Долгие операции выполняются через единую durable JobQueue с состояниями и событиями; `Last-Event-ID`/последовательность события позволяют продолжить чтение без повторной генерации или побочного действия. **Событие «команда начата» не доказывает успешного результата внешней ОС-операции.**

## Плагины и внешние эффекты

Обычный `PluginPlan` только описывает возможные внутренние JSON-изменения. Внешняя команда или сетевое действие получают отдельный предпросмотр и самостоятельное подтверждение. Общий `/accept` не должен запускать внешний процесс. Система фиксирует `started` до вызова ОС и после сбоя переводит неизвестный исход в `unknown` без автоматического повторного исполнения. Проверка прав и точного ресурса выполняется снова непосредственно перед запуском.

Недоверенный код не получает доступ к FastAPI/JSON-менеджеру напрямую. Подробности и известные ограничения: [безопасность расширений](PLUGIN_SECURITY.md) и [внешние действия](PLUGIN_EXTERNAL_EFFECTS.md).

## Файловое хранение и резервирование

JSON — единственный authoritative формат доменных структур, медиа хранятся отдельно. Прямое редактирование файлов в обход API не поддерживается. Полный архив создаётся из согласованного снимка, затем проверяется по манифесту и SHA-256. API диагностики не включает личный корпус по умолчанию; запрос с журналами требует осознанного выбора в интерфейсе и последующей ручной проверки архива.
