# Чат, ветви и изоляция состояний

Внутренняя реализация этапа 06. Полная художественная/аппаратная приёмка остаётся отдельной задачей. Все изменения идут через JSON transaction manager.

## История, состояние и сообщения

Story содержит собственные snapshots карточек (base card revision + полный payload), независимый active_branch и optional world/scenario IDs. Каждая branch имеет свои segments, immutable state snapshots, состав сцены/очередь NPC, главы/закладки/checkpoints и view_mode. Состояния memory/relationships/world/RPG/character_states не разделяют изменяемые объекты с другой историей/ветвью. Scene — реальный UUID/state, состав и очередность; география/календарь расширяются в 09.

Сообщения имеют UUID, story/branch UUID, role/author, UTC time, version, model/profile, source/event/file IDs, state boundary и present_ids. User role всегда author_id=null и не требует Persona. Автор assistant обязан быть присутствующим NPC. Raw текст отображается React как текст, не HTML/команды. Model_id заполняется при настоящей генерации; ручные/начальные сообщения не получают выдуманную модель. Prompt profile пока null, полноценное наследование — 07.

История хранится bounded segments (128 сообщений/1 MiB); append и branch/story metadata публикуются одной транзакцией. DOM получает страницу до 100 сообщений, API максимум 500. При закрытии текущего эпизода state pointer предыдущего сообщения фиксируется в bounded tail вместе с append. Изменения после последнего сообщения доступны через branch.state_id. Это избегает отдельного файла checkpoint на каждую реплику и роста manifest из 10k таких записей. При fork прошлого берётся соответствующая историческая граница, не текущее состояние мира.

## Ветви и изменения прошлого

Fork делает независимые сегменты выбранного префикса и клонирует только нужные immutable state snapshots с новым branch scope. Message UUID копий новые, оригинальные IDs сохранены в source_message_ids. Memory source IDs remap, субъективные знания не становятся общими. Для каждого сообщения копии сохраняется его историческое state boundary: nested fork не наследует будущую тайну. Состав/очередь сцены восстанавливаются из state.scene, а не из текущего parent UI.

Edit создаёт ветвь до выбранной точки с новым текстом и увеличенной версией, используя состояние ДО изменённого текста. Последующие сообщения/derived state остаются в оригинале. Delete создаёт ветвь до сообщения только после подтверждения; оригинал не удаляется. Связанные отметки копируются только для допустимого префикса; отметки изменённого текста остаются в оригинале. Named checkpoint содержит собственный immutable state_id; restore создаёт новую ветвь с этим snapshot, текущая линия сохраняется.

Мутирующие API требуют branch_id + expected_revision; смена active_branch в другой вкладке не превращает старую команду в запись в новый scope. Story revision защищает переключение одновременно с публикацией. update_state отвергает data другого story/branch, даже если номера revision совпадают. Поздний LLM-ответ проходит проверки до inference и commit; устаревший результат не публикуется в чат и остаётся job events для явного решения пользователя.

## Генерация и группы

Все chat/group/regenerate задачи используют единую JobQueue. Повторный Idempotency-Key не создаёт второй fork/ответ. Регенерация создаёт альтернативу только внутри единственного handler, после подтверждения loaded model, а не до идемпотентного enqueue. Continue сохраняет исходный prefix; fragment replace требует однозначный фрагмент и детерминированно сохраняет текст вне него, качество самой замены требует live проверки. Это управляемый повторный запрос, не заявление о наличии специального inference endpoint.

Сцена поддерживает вход/уход и порядок. Group job делает указанное пользователем число реплик, проверяет actor/scope/revision на каждом ходе и не создаёт user messages. Cancel не ждёт следующего токена. Частичный ответ хранится отдельно; explicit apply проверяет story/branch/actor, сохраняет сообщение и applied-message marker одной транзакцией. Повтор apply возвращает прежний ID без дубля. Автопринятия частичного текста нет.

## Импорт и перенос

JSONL SillyTavern (первая metadata-строка и mes/is_user) и JSON-массив/объект messages: preview, сопоставление NPC, подтверждение, независимая история одной транзакцией. Unknown metadata/swipes сохраняются; исходные даты без понятного timezone не угадываются, raw дата остаётся в imported_metadata, предупреждение видно. Известные timezone-aware ISO/Unix даты нормализуются UTC. Системные записи импорта не становятся backend system instructions. Все импортированные swipes пока не превращаются автоматически в дерево — это явное ограничение отчёта, не потеря исходных данных. Реальный независимый corpus остаётся открытой проверкой.

Выборочный перенос событий: source/target scope и revisions, preview+confirm, read guard источника, operation UUID ledger. Переносятся записи с provenance и новым UUID/status imported_record; последствия мира не исполняются, память/отношения не копируются. Список NPC, существующих в целевой истории, ограничивает canonical knower_ids; оригинальный список хранится в origin_knower_ids для аудита и не считается знанием получателя. Механизм применения событий валидируется модулем мира 09, а не переносит произвольно чужое состояние.

## Ограничения текущей контрольной точки

Весь prompt/context manager и quality checks — 07; полноценная память/секреты — 08; мир/временные события — 09; режиссёр — 10; media scene studio — 12. Смена трёх видов чата не меняет текст; визуальная новелла на этом этапе использует сохранённый портрет/реплику, расширенная композиция появится с реальным media модулем. До 07 контекст ограничен последними 50 сообщениями и собственным описанием говорящего, это не завершённый CTX-001–009. Composer предупреждает о неотправленном тексте при выходе; полный autosave всех форм отслеживается UI-011 отдельно.
